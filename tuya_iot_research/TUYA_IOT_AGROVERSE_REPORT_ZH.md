# Agroverse 农场监测 — 深度调研（无线电数据采集）

**为 TrueSight DAO / Agroverse 编制** — 基于与 Erica 与 Gianluca 的办公室会面，以及 SunMint 农户合作伙伴的现场调研。

> **名称说明：** 当时听到的“Tuyao”，对应的是 **涂鸦智能（Tuya Inc. / Tuya Smart）**— tuya.com，已通过办公室合影确认。本报告不绑定供应商：以无线电数据采集架构为主线，涂鸦只作为参考平台选项之一。

---

## 1. 摘要

- **问题：** 亚马逊地区的合作农场（Bahia 巴依亚、Pará 帕拉）处于无网状态 — 边缘没有可靠互联网，暴雨天气中移动网络/卫星链路反而最先衰落。依赖互联网的 IoT 模式是错的。
- **架构：** **无线电数据采集** — 传感器本地记录到 RF 数据记录仪（LoRa / 子 GHz / VHF-UHF）；**车载或无人机数据搬运（data mule）** 按存储转发采集数据；太阳能 + 电池供电可连续运行多年。耐暴雨、零数据丢失、不需要互联网。
- **获得的数据：** 连续的**土壤质量时序数据**、**气象**、**生物多样性**（随森林恢复）、**可可豆品质 × 环境**关联、以及 SunMint 植树计划的**树木健康/存活监测**。
- **平台层：** 存储、仪表盘和分析可以用 **涂鸦**（参考选项 — App 平台强大、有 M0L0 智慧农业产品线），也可以用我们自己的开放技术栈。无线电边缆层与两者都兼容。
- **使命关联：** 每一公顷被实测数据覆盖，都让我们更接近 **10,000 公顷亚马逊雨林恢复** 的目标。

---

## 2. 问题 — 亚马逊的无网农场

- 合作农场（Oscar（巴依亚）、Paulo（帕拉））**没有可靠的互联网**。常规 IoT 前提是边缘能连接云端 — 这里不成立。
- 暴雨是最坏情况：大雨和大风会让 **移动网络和卫星链路最先失效** — 正好在你最需要数据的时候。
- 我们需要 **连续的环境数据** — 土壤、气象、生物多样性、树木健康 — 用于证明恢复与精品质。
- 结论：采用 **无线电数据采集**（RF 遥测 + 本地数据记录仪 + 数据搬运），而非 IoT。可以装在汽车或无人机上，在田间采集数据。

---

## 3. 无线电数据采集架构（正确的传输方式）

*来自 Gianluca 的贡献（办公室会面）：无线电传输在农场上效果很好。*

- **传感器保持本地。** 土壤湿温度、NPK/pH、气象、水质传感器通过有线或短距离 RF 连接到 **田间数据记录仪 / RF 节点**（LoRa、子 GHz 或 VHF/UHF 遥测）。
- **无线电是主干。** RF 链路（LoRa/子 GHz：每跳几公里、低功耗；VHF/UHF：远距离、比移动网络更耐暴雨）把数据从节点传到农舍或村庄的 **本地网关/基站**。每一跳都不需要互联网。
- **数据搬运采集。** 在固定网关覆盖不到的区域：
  - **车载搬运** — 车载无线电/网关（或笔记本 + SDR）行驶通过或接近农场，自动收集范围内节点数据（存储转发）。
  - **无人机搬运** — 携带 LoRa/RF 收发模块的无人机按路线飞过农场，从地面节点下载数据（已在远程无基础设施场景验证；LoRa-UAV 数据采集是活跃的研究领域）。
- **存储转发同步。** 节点本地缓冲数据（SD 卡/闪存）；当搬运工具或上行链路出现时（村里 Wi-Fi、卫星终端、定期 4G），数据同步到云端 — 我们的分析或平台 — 间隙保留并打时间戳。
- **耐暴雨。** 无线电链路（尤其 VHF/UHF 和 LoRa 扩展频谱）在大雨和暴雨中远比移动网络/卫星稳定；本地存储意味着即使链路断开数天也不会丢数据。
- **能源。** 节点采用太阳能 + 电池，可无人值守多年；无线电 + 低功耗 MCU 保持微小功耗预算。

**平台的位置：** 云端分析/App 层只在搬运工具或上行链路同步时接收数据。无线电边缘层不绑定供应商，与任何平台都兼容。

## 4. 我们需要的传感器类别

| 传感器类别 | 测量内容 | 相关性 |
|---|---|---|
| 土壤湿度 + 温度 | 含水量、土壤温度 | 核心土壤质量时序 |
| 土壤 NPK / EC / pH 探头 | 营养、电导率、酸碱度 | 土壤肥力随季节变化 |
| 气象站 | 温度、湿度、降雨、风 | 每个区域的微气候 |
| 水质/水位 | 水罐、井、水库 | 农场用水安全 |
| 摄像头/视觉 | 视觉监控、延时摄影 | 冠层生长、野生动物 |
| 生物声学/摄像陡伏 | 物种存在、活动 | 生物多样性指数 |
| 虫害传感器 | 虫害压力、灌溉 | 作物健康 |

长距离 **LoRa / Sub-1GHz** 变体对亚马逊至关重要：低功耗、单节点覆盖数公里、在移动网络不覆盖处仍可工作。**VHF/UHF 遥测** 在大雨季节最稳定。

## 5. 数据平台层 — 选项

**需求：** 时序存储、仪表盘、能与 QC 记录联合的 API/webhook、数据导出与所有权。

- **选项 A — 涂鸦（参考平台）：** 启动快，生态庞大（大量涂鸦兼容传感器），App SDK 可打造品牌农户 App，有 M0L0 智慧农业产品线和 LoRa 边缘网关。注意：它是平台而非成套农业系统 — 我们需要自己组装。
- **选项 B — 开放技术栈：** InfluxDB/PostgreSQL 时序数据库 + Grafana 仪表盘 + 自建 API。完全控制、数据主权、无供应商锁定；但开发量大。
- **选项 C — 本地集成商：** 巴西农业科技合作伙伴（如 Landatel、Nova Digital）组装传感器 + 网关 + 数据搬运，可能基于涂鸦等平台。

**建议：** 选择能让我们最快在一个农场试点的方案（可能是涂鸦或本地集成商）；保持数据导出开放，以便随时切换或自运分析。

## 7. Agroverse 应用场景

### 7.1 土壤质量随时间变化（农场监测）

- 在 Oscar 农场（巴依亚）与 Paulo 农场（帕拉）部署土壤湿度/温度 + NPK/pH 探头。
- 连续时序数据本地记录在 **RF 数据记录仪**；通过 **车载/无人机数据搬运** 存储转发同步到平台云；建立仪表盘跟踪退化牧场 → 可可农林的恢复进程。
- RF 节点（LoRa/子 GHz）+ 本地网关 + **车载/无人机数据搬运采集**；太阳能 + 电池可无人值守多年。农场无需互联网。

### 7.2 随森林恢复的生物多样性监测

- 第 0 年建立基线，每年测量：树木物种多样性、动物/鸟类存在（生物声学 + 摄像陡伏）。
- 声学监测（AudioMoth 类）在雨林场景已得到验证；音频本地记录，数据搬运采集，离线分析。
- 发布每块地的 **生物多样性指数** 随时间变化 — 这就是可测量的恢复故事。

### 7.3 可可豆品质 × 环境关联

- 科学依据：季节内的降雨、最高温和风速会显著影响发酵和风味（PMC11353615 — 九个农气候聚类；最高温/风速越高，果仁味越浓；发酵超过 ~120 小时果香下降）。
- 发酵结果对温度和湿度敏感（理想 ~45–50°C、高湿度） — 环境数据可直接指导何时停止发酵（96h 还是 120h）。
- 切分评级（坎尘/紫色/棕色）可预测免疑氨酸和多酚谱 — 即驱动巧克力风味的化学基础（PMC6525676）。

### 7.4 品质关联的 Agroverse 应用

- 每批的环境指纹 + 质量等级挂到每个袋子的 **QR 谱系** → TrueChain 公证。“这袋可可：B 区、土壤湿度 X、降雨 Y、发酵 96h、棕色 85% — 精品。”
- 季节学习：“果实长得关键期土壤湿度低于阈值的区域，棕色比例高 15%” → 指导灌溉/种植。
- 用数据为精品定价提供依据；识别 Oscar（巴依亚）和 Paulo（帕拉）农场中可获得溢价的微区域。
- QC 流程：农户/采后团队通过轻量级 App（或实验室表单）拍照切分可可；批次 QR 将照片 + 得分与传感器时间窗联结。平台云存时序数据；我们的账本存联合记录。

### 7.5 数据表结构（每批）

| 字段 | 来源 |
|---|---|
| batch_id / QR | 账本 |
| 农场 / 区域 | 账本 |
| 采收日期 | QC 表单 |
| 发酵时长 | QC 表单（小时） |
| 切分 %棕色/紫色/坎尘 | QC 照片 + 表单 |
| 发酵指数 | 计算 |
| 粒数/100g、湿度 % | QC 表单 |
| 风味笔记 | 尝试员 |
| 土壤窗口（湿度/温度/pH/NPK 均值） | 平台云（自动） |
| 气象窗口（降雨/温/湿/风） | 平台云（自动） |
| 质量等级（A/B/C） | 计算 |

### 7.6 树木健康与存活监测（SunMint 联动）

同样的存储转发理念已经在 **SunMint 农户 App** 里（离线队列 + 上报）。树木健康监测在其上加两层：先用人工打卡，等 RF 层部署后再用传感器交叉验证。

**第一层 — 简单离线界面（先上线，无需新硬件）：**
- 农户 App 已经支持离线登记植树（现场签名、IndexedDB 队列、有信号后自动上报）。
- **扩展为定期健康打卡：** 树木照片 + 存活状态（健康 / 长势不佳 / 死亡）+ 可选 GPS。同一个离线队列，田间一键完成。
- 人工基线：成本低、有人工核实，本种植季即可启动。

**第二层 — 无线电/RF + 数据搬运（自主层，Gianluca 的方案）：**
- 每棵树/每个样方部署低成本传感器：土壤湿温度、气象节点、延时摄影/声学用于冠层与生物多样性。
- 数据本地记录在 RF 数据记录仪；车载或无人机数据搬运按存储转发采集。
- 传感器与农户打卡交叉验证：“健康” + 传感器一致 = 强证据；“健康” + 土壤湿度骁降 = 派人巡查。这才是可信的 MRV，而不是自我报告。

**第三层 — 账本挂钩（回报）：**
- 每棵树已有 QR / 谱系记录。把存活事件（打卡、传感器快照）挂到该树的谱系 → TrueChain 公证。
- 每个队列/样方的存活率成为可测量、可审计的指标 — 正是碳方法学（Verra VM0017 / ARR）要求的：存活率阈值、30 年监测。

**建议：** 不必等传感器。离线打卡扩展直接复用现有 IndexedDB 队列模式，本季就能拿到存活数据；RF 层在硬件部署后补上自主交叉验证。

## 8. 与 Agroverse 技术栈的契合

- **QR 谱系（lineage-credentials / lineage-assets）：** 传感器数据为每个来源记录添加环境证据层。
- **TrueChain（PoA 公证）：** 将定期土壤/生物多样性/质量快照铹定为公证记录。
- **DApp / truesight.me 仪表盘：** 农场监测图表丰富公开的“来源与恢复”展示。
- **注意力表面：** 将“来源与恢复”从叙事变成 **实测数据** — 最强的使命信号。

## 9. 差距、风险与考量

| 领域 | 考量 |
|---|---|
| 名称/拼写 | 已通过办公室合影确认涂鸦；需确认 Erica 公司实际赎售/建设什么 |
| 需要组装 | 平台不是成套农业解决方案 — 我们需选传感器/网关，可能通过本地合作伙伴（如 M0L0、Landatel、Nova Digital） |
| 连接性 | 亚马逊农场可能没有移动网络 — 规划 LoRa + 边缘网关 + 定期同步（数据搬运） |
| 生物多样性传感器 | 生物声学（AudioMoth 类）与摄像陡伏属小众；可能需自定义固件或配套技术栈 |
| 数据所有权 | 确认数据导出、私有云选项（对数据主权而言） |
| 成本 | 每公顷成本低（部分平台约 BRL 1/ha），但硬件 + 网关是真正的预算大头 |
| 安全 | 审查巴西农场数据的存储地域合规性 |
| QC 一致性 | 切分评分需标准化流程 + 照片记录，使各农场、各季节的批次等级可比 |
