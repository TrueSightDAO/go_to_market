## 3. 应用开发平台

- **IoT Core（PaaS）：** 设备全生命周期管理 — 接入、OTA 升级、实时监控、远程控制。
- **TuyaOS / TuyaOpen：** 开放设备 SDK（C/C++），支持 MCU 与 SoC 目标（涂鸦 T 系列、ESP32、树莓派、Rockchip）— 可构建定制传感器固件。
- **App SDK / OEM App / Smart MiniApp：** 无需从零开发即可推出自有品牌农户 App。
- **云端开发：** 设备日志、数据分析、数据可视化、实时音视频、SaaS 开发框架、开放 API。
- **协议：** Wi-Fi、Zigbee、蓝牙、Thread、Sub-1GHz、LoRa（经网关）、NB-IoT、LTE、GPRS。

**结论：** Agroverse 可以实现 传感器 → 涂鸦云 → 定制看板/App，几乎无需自建基础设施。

## 5.5 无线电数据采集与数据搬运架构（亚马逊的正确传输方式）

**关键修正：这不是 IoT。** IoT 假设边缘端有互联网连接。亚马逊（巴伊亚、帕拉）的合作农场没有可靠的互联网 — 而在暴风雨期间，蜂窝/卫星链路最先失效。**无线电数据采集** 是无需互联网传感场景中久经验证、抗风暴的模式：

- **传感器保持本地。** 土壤温湿度、NPK/pH、气象与水质探针通过有线或短距离 RF 连接至 **田间数据记录仪 / RF 节点**（LoRa、Sub-1GHz 或 VHF/UHF 遥测）。
- **无线电是骨干。** RF 链路（LoRa/Sub-1GHz：单跳数公里、低功耗；VHF/UHF：远距离、比蜂窝更抗风暴）将数据从节点传到农场房屋或村庄的 **本地网关/基站**。任何一跳都无需互联网。
- **数据搬运（data mule）采集。** 在没有固定网关覆盖的区域：
  - **车载搬运** — 车辆搭载无线电/网关（或笔记本电脑 + SDR）在农场内或附近行驶，自动采集范围内节点的数据（存储转发）。
  - **无人机搬运** — 无人机搭载 LoRa/RF 收发器按航线飞越农场，从地面节点下载数据（已在无基础设施偏远地区得到验证；LoRa-UAV 数据采集是活跃且文献充分的领域）。
- **存储转发同步。** 节点在本地缓冲数据（SD 卡 / 闪存）；当搬运工具或上行链路出现时（村庄 Wi-Fi、卫星终端、周期性 4G），数据同步至云端 — 涂鸦或我们自己的分析栈 — 缺口保留并打时间戳。
- **抗风暴能力。** 无线电链路（尤其 VHF/UHF 与 LoRa 扩频）在暴雨与风暴中的表现远好于蜂窝/卫星；本地存储意味着即使链路中断数天也不丢失数据。
- **能源。** 节点采用太阳能 + 电池，可多年无人值守；无线电 + 低功耗 MCU 使功耗预算极小。

**涂鸦的位置：** 涂鸦是云端/分析/App 层，*不是* 边缘传输。Agroverse 组合使用：(1) 来自无线电/农业科技供应商的 RF 传感器节点 + 数据记录仪（本地、无需互联网）；(2) 车载/无人机数据搬运采集；(3) 数据到达上行链路后，由涂鸦云（或我们自己的技术栈）负责存储、看板与 可可豆品质 × 环境 分析。

## 6. 对 Agroverse 的相关性 — 三大用例

### 6.1 土壤质量随时间变化（农场监测）

- 在 Oscar 农场（巴伊亚）与 Paulo 农场（帕拉）部署土壤温湿度 + NPK/pH 探针。
- 连续时序数据 **在 RF 数据记录仪上本地记录**；通过 **车载/无人机数据搬运** 存储转发同步至涂鸦云；构建看板追踪退化牧场 → 可可农林复合系统恢复过程。
- 蜂窝信号弱或无信号处使用 RF 节点（LoRa/Sub-1GHz）+ 本地网关 + **车载/无人机数据搬运采集**；太阳能/电池供电，可多年无人值守。农场无需互联网。

### 6.2 森林恢复过程中的生物多样性监测

- 随着土地重新种树，追踪 **冠层/延时摄像头**、**声学传感器**（鸟类/哺乳动物）、**气象站**、**土壤恢复**。
- 涂鸦平台负责设备群与数据管道；物种识别分析构建于其上（可自建或集成数据层）。
- 今天的基线 → 逐年可量化的生物多样性提升 = 对合作伙伴、资助方与 DAO 账本最可信的证据。

### 6.3 重新造林 / 植树可追溯性

- 分区域传感器数据与 **QR 谱系** 和 **TrueChain** 记录挂钩 — 每棵树/每袋可可的种植条件均有传感器验证。
- 强化使命叙事："每售出一袋可可即种下一棵树，且我们正在测量土地在恢复。"

## 7. 可可豆品质 × 环境联动

最有价值的联动：把涂鸦的土壤 + 气象时序数据与每个产区可可豆的实际品质挂钩。这把环境监测变成 **品质预测与溢价定价** 工具。

### 7.1 三层模型

1. **环境层（涂鸦传感器）** — 每个农场分区持续的土壤（湿度、温度、pH、NPK/EC）+ 气象（降雨、气温、湿度、风）数据。
2. **豆品层（采后质检）** — 每批次标准可可评级：
   - **切豆检验**：% 棕色（充分发酵）/ 紫色（发酵不足）/ 石板色（未发酵）；精品目标 70–90% 棕色
   - 发酵指数（由切豆检验颜色比例推导）
   - 每 100g 豆数、含水率、壳率、脂肪含量
   - 风味特征（果香、坚果香、花香）— 精品差异化关键
3. **关联与洞察层** — 每批次品质得分与之前的环境窗口（生长季 + 发酵期）关联。跨季节学习分区级规律。

### 7.2 科学依据

- 降雨、最高温度与风会显著影响发酵与风味（PMC11353615 — 九个农业气候簇；最高温度/风越高坚果香越强；发酵超过约 120 小时后果香下降）。
- 发酵结果对温度与湿度敏感（理想约 45–50°C、高湿度）— 环境与土壤数据直接指导何时终止发酵（96 小时 vs 120 小时）。
- 切豆检验等级（石板/紫/棕）可预测游离氨基酸 + 多酚谱 — 即驱动巧克力风味的化学基础（PMC6525676）。

### 7.3 Agroverse 应用

- 每分区环境指纹 + 每批次品质等级挂接到每袋可可的 **QR 谱系** → TrueChain 公证："本袋可可：B 分区，土壤湿度 X，降雨 Y，发酵 96 小时，85% 棕色 — 精品。"
- 季节性学习："灌浆期土壤湿度低于阈值的分区棕色豆比例 +15%" → 指导灌溉/种植。
- 用数据支撑溢价；识别 Oscar（巴伊亚）与 Paulo（帕拉）农场可获溢价的微产区。
- 质检流程：农户/采后团队通过轻量 App（或实验室表单）拍摄切豆检验照片；批次 QR 将照片与得分关联到传感器窗口。涂鸦云保存时序数据；我们的账本保存关联记录。

### 7.4 数据模型（每批次）

| 字段 | 来源 |
|---|---|
| batch_id / QR | 账本 |
| 农场 / 分区 | 账本 |
| 采收日期 | 质检表单 |
| 发酵时长 | 质检表单（小时） |
| 切豆检验 % 棕 / 紫 / 石板 | 质检照片 + 表单 |
| 发酵指数 | 计算 |
| 每 100g 豆数、含水率 | 质检表单 |
| 风味特征 | 品鉴师 |
| 土壤窗口（湿度/温度/pH/NPK 均值） | 涂鸦云（自动） |
| 气象窗口（雨/温/湿/风） | 涂鸦云（自动） |
| 品质等级（A/B/C） | 计算 |

### 7.5 树木健康与存活监测（SunMint 联动）

把无线电数据采集架构接回植树计划：同样的存储转发理念已经在 **SunMint 农户 App** 里
（离线队列 + 上报）。树木健康监测在其上加两层——先用人工打卡，等 RF 层部署后再用传感器交叉验证。

**第一层 — 简单离线界面（先上线，无需新硬件）：**
- 农户 App 已经支持离线登记植树（现场签名、IndexedDB 排队、有信号后自动上报）。
- **扩展为定期健康打卡：** 树木照片 + 存活状态（健康 / 长势不佳 / 死亡）+ 可选 GPS。
  用同一个离线队列，田间一键完成。
- 人工基线：成本低、有人工核实，本种植季即可启动。

**第二层 — 无线电/RF + 数据搬运（自主层，Gianluca 的方案）：**
- 在树木旁或每个样方部署低成本传感器：土壤温湿度、少量气象节点、延时摄影/声学用于冠层与生物多样性。
- 数据本地记录在 RF 数据记录仪；车载或无人机数据搬运按存储转发方式采集。
- 传感器与农户打卡交叉验证："健康" + 传感器一致 = 强证据；"健康" + 土壤湿度骤降 = 派人巡查。
  这才是可信的 MRV，而不是自我报告。

**第三层 — 账本挂钩（回报）：**
- 每棵树已有 QR / 谱系记录。把存活事件（打卡、传感器快照）挂到该树的谱系 -> TrueChain 公证。
- 每个队列/样方的存活率成为可测量、可审计的指标——正是碳方法学（Verra VM0017 / ARR）
  要求的：存活率阈值、30 年监测。

**建议：** 不必等传感器。离线打卡扩展直接复用现有 IndexedDB 队列模式，本季就能拿到存活数据；
RF 层在硬件部署后补上自主交叉验证。
